# MiniMind Experiment Identity Model

> Version: 1.0 — 2026-08-11
> Canonical identity hierarchy for the MiniMind Research Platform

---

## 1. Identity Hierarchy

```
ResearchExperiment (definition/plan)
    │
    └── ResearchRun (execution record)
           │
           ├── Checkpoints (training state snapshots)
           ├── Metrics (per-step training data)
           └── Evaluation (generation before/after)
```

### Research Session

A **ResearchSession** is a *UI workspace entity*, not a training identity. It represents a user's interactive session in the Research Studio — the working state while configuring and monitoring experiments. It is transient by design and stored in `localStorage` under `minimind-research-workspace`.

**Identity**: `rs-{timestamp}-{random}`  
**Purpose**: UI workspace state (which experiment is being configured, live metrics display, timeline)  
**Lifecycle**: created → configured → queued → running → paused → completed | failed  
**Storage**: `ResearchWorkspace` → localStorage key `minimind-research-workspace`

### Research Experiment

A **ResearchExperiment** is the *canonical experiment definition* — the PLAN. It specifies what model, what dataset, what training config, and what seed. It does NOT contain training results.

**Identity**: `exp-{timestamp}-{random}`  
**Purpose**: Immutable experiment plan (model + dataset + recipe + seed)  
**Lifecycle**: draft → ready → running → completed → archived  
**Storage**: `ResearchExperimentStore` → localStorage key `minimind-research-experiments`

### Research Run

A **ResearchRun** is a *single execution* of a ResearchExperiment. One experiment can have many runs (different seeds, reproducibility verification, ablation variants).

**Identity**: `run-{timestamp}-{random}`  
**Purpose**: Execution record (metrics, generation output, analysis, reproducibility)  
**Lifecycle**: pending → running → completed | failed | cancelled  
**Storage**: `ResearchExperimentStore` → localStorage key `minimind-research-runs`

### TrainingRunRecord

A **TrainingRunRecord** is the *observability record* — extended per-step history data that is too large for the aggregate `ResearchRun`. It holds the full loss/LR/throughput/perplexity history arrays.

**Identity**: Free-form `id` string  
**Purpose**: Full per-step training history for visualization and analysis  
**Lifecycle**: running → completed | failed  
**Storage**: `TrainingMetricsStore` → localStorage key `minimind-training-metrics`

### ExperimentRecord (Phase 51 — Superseded)

An **ExperimentRecord** is a *legacy history record* from Phase 51. It has been superseded by `ResearchRun` + `TrainingRunRecord`. New code should use `ResearchRun` for aggregate results and `TrainingRunRecord` for per-step history.

**Identity**: Free-form `id` string  
**Purpose**: Legacy — superseded by ResearchRun  
**Storage**: `ExperimentStore` → localStorage key `minimind-experiment-history`

### Checkpoint

A **Checkpoint** is a *saved training state* at a specific step. It captures model parameters, optimizer state, scheduler state, RNG state, and DataLoader position — sufficient for exact training resumption.

**Identity**: File path or checkpoint ID string  
**Purpose**: Training resumption and reproducibility verification  

### Fingerprint

A **Fingerprint** is a *reproducibility identity* — an FNV-1a 32-bit hash of the experiment configuration. It answers: "Would running this same config produce the same results?"

**Identity**: 8-character hex string (FNV-1a 32-bit)  
**Purpose**: Configuration identity for reproducibility, NOT runtime identity  
**Generated by**: `ReproducibilityCertificate.generateFingerprint()`

## 3. Key Distinctions

### Session Identity ≠ Experiment Identity

A **ResearchSession** is what the user sees in the UI.  
A **ResearchExperiment** is what gets run.  
They are distinct because:
- One session can configure multiple experiments
- One experiment can be run across multiple sessions
- Sessions are ephemeral UI state; experiments are persisted research artifacts

### Experiment Identity ≠ Run Identity

A **ResearchExperiment** is the plan.  
A **ResearchRun** is one execution of that plan.  
```typescript
// Same experiment, two runs (different seeds)
const exp = createResearchExperiment({ name: "LR Sweep", seed: 42, ... });
const run1 = createResearchRun(exp.id, 42);  // seed 42
const run2 = createResearchRun(exp.id, 123); // seed 123
```

### Run Identity ≠ Fingerprint

A **ResearchRun** has a runtime identity (`runId`).  
A **Fingerprint** is a configuration hash.  
- Two runs with different seeds have different `runId`s but the same fingerprint (if config is otherwise identical)
- A fingerprint proves "these runs used the same configuration"
- `runId` proves "this is a specific execution"

## 4. Known Issues & Fixes Needed

### P0: sessionId / runId Naming Confusion

**File**: `src/lib/minimind/research/TrainingEventBus.ts`  
**Issue**: Event data types use `sessionId: string` but `ResearchExperimentRunner` passes `run.runId`  
**Fix**: Either:
- (A) Rename `sessionId` → `runId` in TrainingEventBus event types (breaking change to subscribers)
- (B) Add both `sessionId` and `runId` fields — deprecate `sessionId` over time
- **Recommended**: Option (A) — rename to `runId`. The event bus is internal; subscribers are few.

### P1: TrainingRunRecord.id is free-form

**Issue**: No standard format for TrainingRunRecord IDs.  
**Recommendation**: Use `run-{ts36}-{rand6}` format matching ResearchRun, or store `runId` as a foreign key.

### P1: No sync between stores

**Issue**: A completed `ResearchRun` is saved to `ResearchExperimentStore` but not to `TrainingMetricsStore` or `ExperimentStore`.  
**Fix**: Add `syncRunToMetricsStore()` and `syncRunToHistoryStore()` functions in the adapter layer.

## 5. Canonical Data Flow

```
User creates experiment via UI
        │
        ▼
ResearchExperiment (id: exp-xxx)
        │
        ▼
ResearchExperimentRunner.run(experiment)
        │
        ├──► createResearchRun(experiment.id, experiment.seed)
        │       → ResearchRun (runId: run-yyy, experimentId: exp-xxx)
        │
        ├──► TrainingExecutor.execute()
        │       → produces TrainingExecutionResult
        │
        ├──► completeResearchRun(run, results)
        │       → ResearchRun populated with metrics
        │
        ├──► ResearchExperimentStore.createRun(run)
        │       → persisted to localStorage
        │
        └──► [Adapter layer should sync to TrainingMetricsStore]
                → per-step history available for observatory
```

## 6. TypeScript Type Reference

```typescript
// Canonical identity types
type SessionId = string;    // "rs-{ts}-{rand}"
type ExperimentId = string; // "exp-{ts}-{rand}"
type RunId = string;        // "run-{ts}-{rand}"
type Fingerprint = string;  // 8-char hex

// Identity hierarchy
interface ExperimentIdentity {
  experimentId: ExperimentId;
  runId: RunId;
  fingerprint: Fingerprint;
}

// A completed experiment result
interface CompleteExperimentResult {
  definition: ResearchExperiment;   // What was planned
  run: ResearchRun;                 // What happened (aggregate)
  history: TrainingRunRecord;       // Per-step details
  fingerprint: Fingerprint;         // Configuration identity
}
```
